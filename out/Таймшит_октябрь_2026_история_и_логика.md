Задачи той же профессии соседнего грейда (тот же вид работ, сначала тот же грейд) — только если своих не хватает по срокам или для второй CAPEX-задачи. | R3 | У кого есть CAPEX — не менее 2 CAPEX-задач: основная ~70%, вторая ~30% (кратно 8 ч, не менее 16 ч, не более половины). 100% OPEX — одна задача, как в сентябре; вторая только если упираемся в лимит. |
| R4 | ≤ 350 ч на задачу в месяц (суммарно по всем сотрудникам); ≤ 8 ч × ставка × рабочие дни сотрудника без отпуска в периоде работ по задаче; на любом отрезке пересекающихся сроков задач сумма часов не превышает ёмкость (проверка по всем парам начало/конец). |
| R5 | Преемственность: задачи сентября, которые продолжаются в октябре, сохраняются (OPEX «(3 кв. 2026)» → «(4 кв. 2026)»); если в сентябре была содержательная разбивка (2+ задачи по ≥ 16 ч) — пропорции сохраняются. |
| R6 | Новые задачи — сначала незанятые / наименее загруженные (покрытие каталога); вторая — из того же эпика. |
| R7 | Строк < 8 ч не оставляем (добиваются до 8 ч за счёт основной задачи того же признака); лишние CAPEX-строки < 16 ч при 3+ CAPEX-задачах вливаются в другие. |
| R8 | Строки сотрудника — по убыванию часов (как в сентябре). |

Даты работ = срок задачи ∩ октябрь; отпуск в начале/конце периода сдвигает дату начала/окончания на первый/последний рабочий день. Часы — целые при ставке 1, с точностью 0,1 при неполной ставке. Комментарий — только из октябрьского исходника.

## 5. Алгоритм `fill_timesheet_oct.py` (фазы)
1. **Таргеты**: CAPEX/OPEX-часы сотрудника по R2.
2. **Фаза 1 — преемственность**: сентябрьские задачи своей должности, активные в октябре, получают часы (CAPEX — основная = C − вторая, или сохранение пропорций сентября; OPEX — вся OPEX-часть на основную).
3. **Фаза 2 — добор**: основная CAPEX-задача (если нет), затем вторая и далее до закрытия часов; если часы закрыты, а задача одна — вторая выделяется переносом из основной. OPEX — доливка до таргета. Выбор кандидата: уже назначенная → предпочтение сентября → близость грейда → достаточный запас → тот же эпик → меньшая загрузка.
4. **Фаза 3**: если своих задач не хватило по срокам — CAPEX на задачи соседнего грейда той же профессии, затем остаток на задачи другого признака своей должности.
5. **Фаза 4a/4b**: слияние CAPEX-строк < 16 ч, добивка строк < 8 ч.
6. **Запись**: колонки исходника + «Признак», «Вид работ», «Наименование задачи», «Задача», даты, комментарий; стили берутся из исходника; служебный лист «Контроль» (по сотрудникам и по задачам с остатком до 350 ч).
7. Диагностика в консоль: задачи чужой должности, < 2 CAPEX-задач, отклонение долей, нераспределённые часы, превышение 350, использованные переименованные задачи.

## 2. Сквозные правила распределения (R1–R8)

| № | Правило |
|---|---|
| R1 | Задачи своей должности по каталогу, активные в месяце. Задачи той же профессии соседнего грейда (тот же вид работ, сначала тот же грейд) берутся, только если своих не хватает по срокам или для второй CAPEX-задачи |
| R2 | Доли CAPEX: менеджеры продукта (и ведущие) 60/40; руководители команд 30/70. 100% OPEX: директор департамента, руководители управлений и направлений, менеджер и руководитель проектов, инженеры сопровождения. Остальные — 100% CAPEX |
| R3 | У кого есть CAPEX — не менее 2 CAPEX-задач: основная ~70%, вторая ~30% (кратно 8 ч, не менее 16 ч). У 100% OPEX — одна задача; вторая только при лимите |
| R4 | Не больше 350 ч на задачу в месяц по всем сотрудникам. Часы строки не больше ёмкости сотрудника в периоде работ (ставка × часы рабочих дней без отпуска). На пересекающихся сроках задач сумма часов не превышает ёмкость |
| R5 | Преемственность с прошлым месяцем: продолжающиеся задачи сохраняются (применялась в октябре; в ноябре нет — см. раздел 7) |
| R6 | Новые задачи берутся сначала незанятые или наименее загруженные; вторая задача — из того же эпика |
| R7 | Строк меньше 8 ч нет; лишние CAPEX-строки меньше 16 ч (при 3+ CAPEX-задачах) вливаются в другие |
| R8 | Строки сотрудника идут по убыванию часов |

Общие правила оформления:
- даты работ = срок задачи в пределах месяца; отпуск в начале или конце периода сдвигает дату;
- часы целые при ставке 1, с точностью 0,1 при неполной ставке;
- комментарий — только из исходника месяца;
- остальные листы исходника не меняются;
- каждый месяц результат проверяет независимый скрипт, код которого не связан с распределением.

Соответствие должностей: «Начальник отдела» → «Руководитель команды», «Специалист ML» → «Ведущий специалист ML».

## 5. Консультация отдела капитализации ФОТ (МСФО), ноябрь: правила

- **Формула названия CAPEX-задачи:** [действие] + [объект ПО], из названия виден результат — код, документ, настройка. Подходящие действия: разработка, доработка, настройка, тестирование, интеграция, написание технических документов.
- **Слова, из-за которых задача уходит в OPEX:**
  - исправление ошибок, корректировка, устранение дефектов, рефакторинг из-за качества;
  - «анализ», «системный анализ», «исследование» — нужно писать созданный артефакт: «написание ТЗ / спецификации»;
  - работа с данными (миграция, загрузка остатков, актуализация справочников) — капитализируется только создание инструмента;
  - административная работа: найм, обучение, презентации, совещания без задачи разработки;
  - аббревиатуры и жаргон.
- **Без синонимов:** «разработка» вместо «формирования», «генерации», «проектирования».
- **Одна строка — один вид работ.** Если в строке смешаны работы, система ставит OPEX.
- **Поле «Технический продукт»** обязательно, без него задача не попадёт в капитализацию.
- **Переименовать задачу нельзя.** Если в прошлом месяце задача получила OPEX или неверный тип, старую нужно закрыть и завести новую.
- **Автораспределение допустимо,** но отвечает за корректность руководитель проекта. Часы распределяются по фактически выполненной работе.
